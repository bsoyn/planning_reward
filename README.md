# 갓생 포인트

계획 달성 → 포인트 획득 → 보상 구매로 동기부여하는 개인용 앱.

## 구조

```
src/
  index.html            개발용 진입점 (이 파일을 브라우저로 열면 바로 실행됨)
  styles.css            전체 스타일
  core/
    utils.js            공통 유틸, 이벤트 버스(pub/sub), 토스트
    store.js            상태 저장소 (localStorage 영속화)
    app.js              앱 셸: 탭 라우팅, 렌더 오케스트레이션, 컴포넌트 레지스트리
    boot.js             부트스트랩
  services/
    points.js           포인트/스트릭/레벨 계산 (순수 로직, DOM 무관)
    schedule.js         계획 스케줄 판정 (순수 로직)
    actions.js          상태 변경 액션 (유일한 상태 변경 창구)
    reconcile.js        일일 정산: 놓친 예정일 방어막 소모/페널티 (순수 로직)
    sync.js             내보내기/가져오기, File System Access 자동 저장
  components/
    common.js           공용 뷰 헬퍼
    hero.js / today.js / plans.js / shop.js / stats.js / settings.js
build.js                단일 HTML 빌드 스크립트
planning_reward.html    빌드 결과물 (폰에 넣어 쓰는 배포용 단일 파일)
```

## 개발 흐름

1. `src/` 안의 파일 수정
2. `node build.js` 실행 → `planning_reward.html`(로컬용) + `docs/`(배포용, PWA 포함) 재생성
3. `git push` → GitHub Pages가 `docs/`를 자동 배포 → 폰에서 같은 주소로 접속

개발 중에는 `src/index.html`을 브라우저로 열면 빌드 없이 바로 확인 가능.

순수 로직 회귀 테스트: `node test.js` (반복 기간·스트릭·마이그레이션·보상 티켓. DOM 없이 실행됨)

## 모바일 (PWA)

- `docs/`에 manifest + service worker가 포함되어 GitHub Pages(Settings → Pages → main / docs)로 배포하면 Android Chrome에서 "홈 화면에 추가" 시 전체화면 앱으로 설치됨. 오프라인에서도 실행 가능.
- 데이터는 폰 브라우저의 localStorage에 저장 — 주소가 같으므로 앱을 업데이트(push)해도 데이터는 그대로 유지됨.
- service worker는 네트워크 우선이라 온라인이면 항상 최신 버전을 로드함. PWA 자산 수정은 `pwa/`에서.

## 아키텍처 규칙

- 상태 변경은 반드시 `PR.actions.*` 를 통해서만 (컴포넌트가 state를 직접 수정하지 않음)
- 액션이 `save()` 후 `change` 이벤트를 발행하면 앱 셸이 전체 리렌더
- 계산 로직(`points.js`, `schedule.js`)은 DOM 의존이 없어 단독 테스트 가능
- 새 탭 추가: 컴포넌트 파일 만들어 `PR.app.register('이름', {render, bind?, onNavAway?})` 호출
  → `src/index.html`에 script 태그 추가 → nav에 버튼 추가 → 빌드

## 포인트 규칙 (v2)

기준 가치: 1P ≈ 100원. 기본P는 계획마다 직접 설정하며 "남이 시키면 최소 얼마 받을까 ÷ 100"을 앵커로 사용 (가볍고 재미있음 10~20P, 무난함 30~50P, 하기 싫고 머리 아픔 80~100P).

계획 유형 (v3): 습관(정해진 시각 없이 주기적으로 하면 좋은 것 — 단순 O/X, 해빗트래커 그리드, 전용 탭), 반복적인 일(목표 T/Q·정시가 있는 반복 작업 — 요일 고정/주 n회), 1회성(목표일이 있는 일), 프로젝트(마일스톤 + 완주 보너스). 반복·1회성에 시간 목표 T(분)와 분량 목표 Q를 걸 수 있고, 비우면 O/X.

반복 기간 (v5): 습관·반복적인 일에 `startDate`/`endDate`를 둘 수 있다. 범위 밖 날짜에는 계획이 아예 예정되지 않으므로, 오늘 추가한 계획이 지난 날짜에 소급 표시되어 스트릭이 끊기거나 30일 달성률이 깎이던 문제가 없다. 판정은 전부 `schedule.js:isScheduledOn`을 경유하므로 달력·오늘·통계·정산이 한 번에 따라온다. 비우면 무제한(시작일 '' = 언제부터든, 종료일 '' = 종료 없음). 기간이 끝난 계획은 습관 그리드에서 빠지고 계획 목록 아래로 내려가며 '기간 종료' 칩이 붙는다. v4 데이터는 "생성일과 최초 기록일 중 이른 쪽"을 시작일로 잡아 마이그레이션 — 생성일만 쓰면 그보다 앞선 기록이 달력에서 사라지기 때문.

의무 플래그: 알바·출근·수업처럼 당연히 해야 하는 일은 "의무"로 표시 — 낮은 P(5~10) 권장, 포인트는 지급되지만 전체 스트릭 카운트에서 제외 (출근만으로 스트릭이 유지되는 것 방지). 습관과 계획에는 각각 개인 스트릭(연속 예정일/연속 충족 주)도 표시.

```
r = 달성률: 목표 없으면 1 / T만·Q만이면 해당 비율
    둘 다 있으면 OR=max(둘 중 하나) / AND=min(둘 다)
지급     = 기본P × min(r,1)^1.5         ← 부분 달성 완화 + 최소 10% 보장
스트릭   = +2%/연속일, 최대 +50%          ← r≥1일 때만
정시     = +기본P×30% (시간대 시작~끝 내 완료,
           끝 미지정 시 시작 ±30분 · 자정 넘김 가능) ← r≥1일 때만
초과     = +기본P×50%×min(r-1,1)         ← 절반 요율, 상한 +50%
조기(1회성)  = +기본P×30%×남은기간비율      ← r≥1, 목표일 전
늦음(1회성)  = 총액 ×80%                    ← 목표일 지남 (-20%)
```

스트릭과 주간 쿼터 카운트는 완전 달성(r≥1)만 인정 (의무·번외 제외). 프로젝트 마일스톤은 O/X이며 완료 즉시 지급, 전체 완료 시 완주 보너스(목표일 있으면 조기/늦음 규칙 동일 적용).

보상과 사용권 (v6): 보상은 **여러 번**(살 때마다 사용권이 쌓임)과 **한 번만**(딱 한 장) 중에 고른다. 구매하면 포인트가 빠지면서 사용권(티켓) 1장이 발급되고, 실제로 누릴 때 상점에서 '사용'을 눌러 소진한다 — 사 두고 아껴 뒀다가 쓰는 흐름. 안 쓴 사용권은 환불(포인트 반환) 가능하고, 잘못 누른 사용은 '되돌리기'로 복구된다. 1회성의 소진 여부는 별도 플래그가 아니라 **남아 있는 티켓에서 파생**되므로 환불하면 자동으로 다시 살 수 있게 된다. 기존 구매 내역은 이미 누린 것으로 보고 사용 완료 상태로 마이그레이션.

번외 기록: 계획에 없던 일도 오늘 탭에서 기록 가능 — 가치의 80% 지급, 보너스·스트릭 없음. 계획하고 실행한 일이 항상 더 값지도록 하는 차등.

레벨 시스템은 제거됨 (칭호만으로는 실효과가 없어서). 재도입 시 이전 공식: n레벨 승급 = 누적 50×n×(n+1)P, 칭호 목록은 git 히스토리 또는 이전 버전 참고.

v1 데이터는 로드 시 자동 마이그레이션 (기본P = 이전 포인트 × 난이도 배율).

## 계획 폼과 용어 (v6)

- **'마감일' → '목표일'**: 이름을 부드럽게 바꾸면서 늦음 감액도 -50% → **-20%**로 완화했다(`points.js:LATE_RATE`). 센 패널티와 부드러운 이름이 어긋나지 않도록 한 쌍의 변경. 화면 문구는 `latePct()`/`lateKeepPct()`에서 만들어 쓰므로 비율을 바꾸면 안내 문구도 같이 따라온다.
- **폼 단순화**: 겉에는 이름 · 언제(요일/목표일) · 포인트만 두고, 목표치·시간대·반복 기간·의무는 `<details class="adv">`에 접었다(반복 폼 기준 노출 항목 11개 → 4개). 접혀 있어도 DOM에는 남으므로 제출 로직은 그대로다. 수정 시 기본값이 아닌 세부 항목이 있으면 펼친 채로 연다.
- **기본 포인트 0 허용**: 포인트 없이 기록만 하는 계획이 가능하다. 빈칸도 0으로 본다. 0P 계획은 화면에 "기록만"으로 표시되고, 정산에서도 차감되지 않는다(예전엔 `Math.max(1, …)` 때문에 0P 계획을 놓쳐도 1P가 깎였다).

## 심리 보강 (v4)

보상 심리를 자극하되 사용자가 새로 조작·결정할 것은 없게(페널티 on/off 토글 하나 제외) 설계. 전부 공식/자동 로직으로만 작동.

- **부분 달성 완화 + 착수 최저보상**: 지급 곡선을 `r²`에서 `r^1.5`로 완화하고, 조금이라도 하면 최소 10% 보장. "완벽 못 하면 시작도 안 함"을 줄임 (완전 달성은 그대로 100%). `points.js:calcAward`
- **서프라이즈 보너스**: 완전 달성 시 13% 확률로 기본P의 20~50% 추가 지급 (변동비율 강화). 미리보기를 흔들지 않도록 계산에서 분리해 완료 액션에서만 굴림. `points.js:rollSurprise`
- **스트릭 방어막(freeze)**: 7일 연속마다 자동 +1 (상한 3). 예정일을 놓치면 방어막이 자동 소모되어 스트릭을 지킴 → "한 번 깨지면 포기"(what-the-hell effect) 방지. 히어로에 🛡 표시. 스트릭은 스케줄 인식으로 바뀌어(예정 없는 휴식일은 스트릭을 끊지 않음) 방어막 규칙과 일관됨. `points.js:computeStreak`
- **놓친 날 소액 페널티**: 방어막이 없을 때만, 놓친 예정일당 기본P의 20% 차감(1회 정산 상한 30P, 포인트는 0 미만으로 안 내려감). 의무·번외·주 n회형 제외, 방어막이 있으면 면제. 손실 회피 레버를 조작 없이 활용하되 과하지 않게. 설정에서 끌 수 있음(기본 켜짐). `reconcile.js`

## 자정 넘김 대응 (v6)

- **하루 시작 시각** (기본 새벽 4시, 설정에서 자정~6시): `PR.todayStr()`을 인자 없이 부르면 "지금이 속한 하루"를 돌려주므로, 새벽에 끝낸 일이 어제 것으로 기록되고 스트릭·정시·서프라이즈 보너스도 그대로 붙는다. 인자를 주면 그 날짜를 그대로 포맷하므로 날짜 순회 루프에는 영향이 없다. 다만 루프의 **시작점**은 `PR.todayDate()`를 써야 한다 — `new Date()`를 그대로 쓰면 새벽에 하루가 어긋나 스트릭이 0이 된다. `utils.js`
- **달력에서 지난 날 완료/취소**: 달력 상세에서 14일 이내의 지난 날짜를 뒤늦게 완료할 수 있다. 목표(T/Q)가 있으면 입력 폼이 열리고, 시간대가 있으면 "그때 시간 안에 했었어요" 체크가 항상 뜬다(`completeForm`의 `forceOnTime`). `calendar.js`
- **정산 되돌리기**: 소급 완료로 그 날이 달성이 되면, 그날 소모된 방어막 1개와 차감된 포인트를 정확히 되돌려준다. 이를 위해 정산 로그에 `days:[{ds,pen}]`로 **날짜별 차감액**을 남긴다(총액만 남기면 환급액을 알 수 없음). 완료를 다시 취소해도 페널티를 재부과하지는 않는다. `actions.restoreForDate` / `reconcile.js`

정산(`reconcile.run`)은 앱 로드 시 하루 1회, `lastReconcile` 다음날~어제 구간만 처리하며, v3→v4 마이그레이션 시 `lastReconcile`을 오늘로 두어 과거를 소급 차감하지 않음. 페널티는 `planId:'penalty'`, 서프라이즈는 완료 로그의 `surprise` 필드로 기록.
